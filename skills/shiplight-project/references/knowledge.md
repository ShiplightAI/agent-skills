# Knowledge Management

As you work on tasks, you will learn things that are not obvious from the code or guides — app quirks, reliable patterns, failure modes, tooling gotchas. Write these down so future agents can benefit.

## When to write

Write a note any time you discover something a future agent would need to know that they could not easily derive themselves. Do not write notes about things already documented in the guides or derivable from reading the code.

## Where to write

All knowledge files live in `knowledge/`.

Pick file names that reflects the topics. If fitting files already exists, update them. If not, create new files. You decide the organization — there are no preset files.

## How to write

Each note must stand alone. A future agent reading it has no memory of your task.

- State the fact, pattern, or gotcha directly
- Include enough context to make it actionable
- No references to "the current task", "what we just did", or specific dates

## When to read

Before starting any task, check `knowledge/` for files relevant to what you are about to do. Knowing what past agents learned can save you from repeating their mistakes.
